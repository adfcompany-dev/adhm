# 프레임워크 기반 웹사이트 고도화 제안서

## 1. 개요
현재 '올데이하우스 묵동' 웹사이트는 `HTML/CSS/JS` 기반의 정적 방식으로 구축되어 있습니다. 이는 가볍고 수정이 직관적이라는 장점이 있으나, 콘텐츠(사진, 룸 타입 등)가 늘어나거나 유지보수를 지속할 경우 중복 코드가 발생하고 관리가 어려워질 수 있습니다.

본 문서는 **Next.js (React 기반)** 프레임워크를 도입하여 사이트를 개선하고 고도화하는 방안을 제안합니다.

## 2. 도입 추천 프레임워크: Next.js
GitHub Pages 배포 친화적이며, **SSG (Static Site Generation)** 기능을 통해 강력한 성능과 SEO(검색 최적화)를 제공하는 **Next.js**를 추천합니다.

## 3. 주요 개선 포인트

### 1) 이미지 최적화 (가장 중요)
*   **현황**: 원본 JPEG 파일을 그대로 로드하고 있어, 모바일 환경에서 데이터 소모가 크고 로딩 속도가 느릴 수 있음.
*   **개선**: `next/image` 컴포넌트 사용.
    *   사용자 디바이스 크기에 맞춰 **이미지 사이즈 자동 리사이징**.
    *   최신 포맷(**WebP**, AVIF) 자동 변환 전송.
    *   **Lazy Loading** 기본 적용으로 초기 로딩 속도 비약적 향상.
    *   이전 작업에서 이슈가 된 '스크롤 길이 문제'도 뷰포트 기반 로딩으로 성능 저하 없이 해결 가능.

### 2) 컴포넌트 기반 구조 (유지보수성)
*   **현황**: `index.html` 파일 하나에 Navbar, Hero, About, Gallery 등의 코드가 모두 들어 있어 코드가 길고 복잡함.
*   **개선**: 재사용 가능한 **UI 컴포넌트 분리**.
    *   `src/components/common/Header.tsx`
    *   `src/components/home/RoomCard.tsx`
    *   `src/components/ui/GallerySlider.tsx`
    *   방 데이터(가격, 호수 등)를 코드가 아닌 **JSON/상수 데이터(`data/rooms.ts`)**로 관리하여, 가격 변동 시 텍스트만 수정하면 일괄 반영됨.

### 3) 데이터 기반 렌더링
*   **현황**: 각 호수별 사진을 위해 `<img>` 태그를 수십 개씩 하드코딩함 (`index.html` 라인 수 증가의 주원인).
*   **개선**: 사진 폴더를 스캔하거나 파일명 규칙을 통해 **반복문(Map)으로 자동 렌더링**.
    ```tsx
    // 예시 코드
    {roomImages.map((src) => (
      <Image src={src} width={400} height={300} alt="Room Photo" />
    ))}
    ```
    사진 추가 시 코드를 수정할 필요 없이 파일만 넣으면 자동으로 갤러리에 뜨도록 구현 가능.

### 4) SEO 및 메타 태그 관리
*   **현황**: 단일 HTML 파일의 `<head>` 태그 관리.
*   **개선**: **Next SEO** 라이브러리 활용.
    *   페이지별/동적 메타 태그 관리 용이.
    *   Open Graph (카카오톡, 슬랙 공유 시 미리보기 이미지) 설정 최적화.

## 4. 마이그레이션 로드맵

| 단계 | 작업 내용 | 예상 소요 시간 |
| :--- | :--- | :--- |
| **Step 1** | **Next.js 프로젝트 초기화** (TypeScript, Tailwind CSS 적용 권장) | 1 시간 |
| **Step 2** | **기존 자산 이관** (`public/images` 폴더로 사진 이동 및 폴더 구조 정리) | 0.5 시간 |
| **Step 3** | **컴포넌트 개발** (레이아웃, 헤더, 푸터, 섹션별 컴포넌트 분리) | 4~6 시간 |
| **Step 4** | **데이터 구조화** (Room 타입, 갤러리 이미지 데이터 상수화) | 2 시간 |
| **Step 5** | **배포 설정 변경** (GitHub Actions 워크플로우를 이용한 Next.js 빌드 및 배포) | 1 시간 |

## 5. 결론
현재 사이트도 기능상 문제는 없으나, **이미지 로딩 속도 개선**과 **향후 유지보수 편의성**(예: 가격 변경, 사진 교체 등)을 고려한다면 프레임워크 도입은 매우 효과적인 투자가 될 것입니다. 특히 '올데이하우스'와 같이 고화질 사진이 많은 사이트는 Next.js의 이미지 최적화 효과를 톡톡히 볼 수 있습니다.
